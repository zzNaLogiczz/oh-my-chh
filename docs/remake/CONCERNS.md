# remakeweb：全面重绘方案的完整风险与实现清单

> 基于登录态实测（59 楼真实帖 + 8 路由提取）的穷举分析。
> 标注 🔴=阻塞性（PoC 必须解决）、🟡=重要（v1 必须）、🟢=可延后。

## A. 安全 —— 帖子 HTML 直接渲染的攻击面 🔴

实测 59 楼内容 HTML（16KB）中：
- **1 个 `<script>` 标签**、**12 个内联 on\* 事件**、**2 个 `javascript:` 链接**
- 帖内还有 `<style>` 标签（会污染重绘层布局）与 Discuz 私有标签 `<ignore_js_op>`

1. 🔴 **HTML 白名单 sanitizer 是硬性前置**：`contentHtml` 不得直接渲染。需要
   DOMPurify（或自研白名单遍历器），策略：只保留格式标签/链接/图片/引用，
   剥离 script/style/iframe/on\*/javascript:。
2. 🔴 **B站 iframe 例外放行**：帖内插 B站视频是官方功能（实测 2 处 player iframe）。
   sanitizer 需域名白名单（player.bilibili.com 等）+ 固定属性。
3. 🟡 **Discuz 私有结构转换**：`<ignore_js_op>`（防抓取包裹标签）剥除；
   `img[zoomfile]`（原图地址）转正图；`img[id^=aimg]` 的点击放大菜单改自有灯箱；
   `<font color/size>` 旧标签转 CSS。
4. 🟡 私信内容同样过 sanitizer（私信里的链接/图片同样不可信）。

## B. 内容结构与渲染保真

5. 🟡 **表情系统**：smilies 是 `<img src=smilies/...>`（实测 5 处），需要
   Discuz 表情码 ↔ 图片映射表；重绘编辑器还要表情选择器。
6. 🟡 **图片布局抖动（CLS）**：实测约 2/3 的帖图无宽高声明，且 `zoomfile`
   指向的大图加载后才会撑开。对策：解析时提取 Discuz 附带的 `width/height`
   （有 1/3 存在）写入占位容器，或渲染后二次校正。
7. 🟡 **特殊帖类型**：投票帖、交易帖（商品信息+交易状态）、悬赏帖、辩论帖的
   内容结构各不相同——解析器需要按 `thread_types` 分型，PoC 先覆盖普通帖。
8. 🟢 引用楼中楼（`<blockquote>` 嵌套）、代码块在其他帖子存在，白名单渲染器
   需覆盖；本帖样本为 0。
9. 🟢 `[hide]` 回复可见内容（实测 2 处标记）：未回复时 Discuz 返回提示块，
   重绘层要能展示"回复可见"状态并引导。

## C. 会话与账号生命周期

10. 🔴 **登录态过期探测与降级**：Discuz 会话较短（实测数小时即失效）。
    每次解析/fetch 需检测"被重定向到登录页/内容含您尚未登录"→ 明确提示
    并引导回原页登录（登录需腾讯滑块，扩展无法代办，只能引导）。
11. 🟡 **审核队列**：chiphell 部分版块发帖进入审核（用户亲历）。提交成功
    响应可能不是成功而是"审核中"——需要识别该文案并如实提示（内容不会
    立即出现在列表）。
12. 🟡 多标签页一致性：多个重绘 tab 并存时，A 页发帖后 B 页不知道——
    保持"每次导航重新解析"（MPA 模式）即可规避，不做跨 tab 状态同步。
13. 🟢 同一账号多设备登录的一般 Discuz 行为不变。

## D. 写操作深水区（工作量最大的一块）

14. 🔴 **BBCode ↔ 富文本转换器**：Discuz 存储 BBCode（[b][i][quote][img]...）。
    重绘编辑器要么做富文本↔BBCode 双向转换器，要么直接做 BBCode 源码
    编辑器（成本差数倍）。回帖（纯文本+表情）简单；**发主题/编辑**是深水区。
15. 🟡 **附件上传**：multipart 接口、大小/格式限制、进度、图片压缩——原页
    由 Discuz JS 处理，重绘需自实现或降级原页上传。
16. 🟡 **编辑自己的帖子**：edit 模式需先拉取原 BBCode 内容填充编辑器。
17. 🟡 **错误响应统一解析**：Discuz 错误 = HTML 内嵌 `show_error` 脚本或
    alert 文案，格式分散；需要统一解析器映射为重绘层的错误提示。
18. 🟡 **发主题完整字段**：分类 typeid（按版块联动）、标签、阅读权限、
    投票选项——快速回帖之外的完整发帖表单。
19. 🟢 防重复提交：formhash 是会话级（可重试），但 UI 层需防双击；网络
    超时后无法确认是否已发出 → 提示用户去原页核实。

## E. 架构与工程

20. ✅ **架构决策（已定）——自包含壳 + 数据驱动空态**：重绘层是插件自有的
    独立应用壳（导航/布局/组件），与原页面**零渲染依赖**；解析数据只是填充物。
    chiphell 改版导致解析失败时，壳照常渲染，内容区显示空态——"白屏"这一
    失败模式被架构性消灭，不需要回退原页的看门狗。配套四态体系：
    loading（骨架）/ empty（空数据）/ partial（块缺失即隐藏）/ error（异常 +
    「查看原页」逃生舱链接——功能降级入口而非渲染依赖）。
21. ✅ **与现有 CSS 方案的共存与切换**：remakeweb 作为独立模式（capability
    或主题项），用户可一键切回 CSS 方案或原版；两套并存时 theme 资产加载
    互斥（CSS 主题 vs 隐藏原 DOM）。
21b. 🟡 **数据源断供的诚实权衡**：壳不依赖原页，但内容数据仍解析自原页。
    Discuz 大改版时：CSS 方案 = 丑但能用；remakeweb = 壳在但内容空白。
    缓解：解析失败遥测（monitoring-log）+ 解析器快速修复 + 每页固定
    「查看原页」逃生舱。这是本方案的核心权衡，已接受。
22. 🟡 **原页 JS 副作用**：隐藏原 DOM 后，Discuz 的通知轮询/Swiper/定时器
    仍在运行（console 噪音、无谓请求）。移除原 DOM 可回收内存并让大部分
    定时器自然报错停止——需要评估移除的副作用（如原隐藏层被 showWindow
    依赖——重绘层已自实现弹窗，无碍）。
23. 🟡 **head 样式残留**：Discuz 的 `style_22_common.css` 仍作用于 host 元素
    本身（继承/全局选择器）；Shadow DOM 隔离内容但 host 在 light DOM——
    需要在 host 上显式 reset。
24. 🟡 **滚动位置恢复**：前进/后退返回长帖时的滚动锚定（原浏览器行为依赖
    原 DOM）；重绘层需自实现（按楼层定位）。
25. 🟡 **锚点跳转**（#lastpost 等）：自实现按 pid/floor 滚动。
26. 🟡 **通知轮询**：原页有未读数轮询；重绘层决定是否自做（频率/功耗），
    或砍掉该功能只显示进入时状态。
27. 🟢 **性能度量方法**：PoC 需 PerformanceObserver 对比原页/重绘页的
    FCP/可读时间/内存，用数据代替感觉。
28. 🟢 **解析器回归测试**：fixtures 快照测试已有基础；增加"线上真实页定期
    校验"与解析失败遥测（monitoring-log 已有基建）。
29. 🟢 Trusted Types / CSP 未来收紧：重绘层 innerHTML 注入需预留 policy。
30. 🟢 Discuz 版本升级风险：X3.5 多年稳定，解析器维护成本低（远低于 CSS
    对抗的成本波动）。

## F. 产品层面

31. 🟡 **搜索**：chiphell 用 Google CSE——重绘层搜索框跳 CSE 页或 Discuz
    搜索结果页（后者可解析重绘，前者跳转即可）。
32. 🟡 渐进发布：thread-detail（阅读收益最大）先行 → thread-list → 门户；
    写页与复杂页长期保留 CSS 方案。
33. 🟢 统计/广告位丢失的产品决策（重绘后不再展示原站统计与推广位）。

## 落地顺序建议

1. sanitizer + 转换器（A 组）——渲染层的地基
2. thread-detail 只读 PoC（B7 之外的普通帖）+ 性能度量（E27）
3. 看门狗与回退（E20/21）——保证永远有可用版本
4. 快速回帖透传（D14 最简形态）+ 审核态提示（C11）
5. 其余按路由渐进
